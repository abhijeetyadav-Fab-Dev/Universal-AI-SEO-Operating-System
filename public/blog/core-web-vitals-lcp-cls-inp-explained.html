Core Web Vitals: LCP, CLS, and INP Explained for Engineers

By Abhijeet Yadav • Published September 18, 2026 • PERFORMANCE ENGINEERING

Google's Core Web Vitals (CWV) are user-centric performance metrics included directly in search ranking algorithms. Rather than measuring arbitrary synthetic speeds, CWV measures how real users perceive loading speed, visual stability, and interaction responsiveness.

The 3 Vital Metrics & Passing Thresholds

Metric What It Measures Good (Pass) Threshold
LCP (Largest Contentful Paint) Perceived loading speed: time required to render the largest visible block (hero image or heading) ≤ 2.5 seconds
CLS (Cumulative Layout Shift) Visual stability: sudden jumps or movement of content as resources load asynchronously ≤ 0.1
INP (Interaction to Next Paint) Interaction responsiveness: latency of clicks, taps, and keypresses across the entire page lifecycle (officially replaced FID) ≤ 200 milliseconds

1. How to Optimize Largest Contentful Paint (LCP)

Preload and Prioritize the Hero Asset

If your LCP element is a background or hero image, ensure it is preloaded in the document <head> and marked with fetchpriority="high":

<!-- Preload hero element in <head> -->
<link rel="preload" as="image" href="/hero-banner.webp" fetchpriority="high">

<!-- In markup -->
<img src="/hero-banner.webp" fetchpriority="high" loading="eager" alt="Hero Banner">

Eliminate Render-Blocking CSS and Fonts

Use modern font formats with font-display: swap and preconnect to font CDNs to prevent FOUT (Flash of Unstyled Text) delays.

2. How to Eliminate Cumulative Layout Shift (CLS)

Always Specify Explicit Dimensions on Media Elements

Unsized images and ads are the #1 cause of layout shifts. Modern browsers calculate aspect ratios automatically when width and height are specified in HTML attributes:

<!-- Explicit dimensions prevent CLS -->
<img src="/product.jpg" width="800" height="450" style="width: 100%; height: auto;" alt="Product">

3. How to Master Interaction to Next Paint (INP)

INP replaced First Input Delay (FID) as an official Core Web Vital. While FID only measured the first interaction, INP evaluates the worst latency interaction across the entire user session. High INP is almost always caused by long JavaScript tasks occupying the main browser thread.

Yield the Main Thread

Break up heavy CPU tasks into chunks using scheduler.yield() or requestIdleCallback():

async function processBatch(items) {
  for (const item of items) {
    processItem(item);
    // Yield to let browser handle user taps and repaints
    if ('scheduler' in window && 'yield' in scheduler) {
      await scheduler.yield();
    } else {
      await new Promise(resolve => setTimeout(resolve, 0));
    }
  }
}
